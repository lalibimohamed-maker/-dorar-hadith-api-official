# AI Video Import & Quran Composition — 2026

## Purpose

Allow a user to bring an AI-generated video into the Encyclopedia Studio and compose verified Quranic material over it. This is a **Studio workflow**, not a video-search feature.

## Pipeline

`External AI generation → user imports video → rights/provenance gate → media validation → Quran text selection → verified recitation selection → Arabic typography → timing/sync → composition → audio validation → export`

## Rights policy

An AI-generated video is **not automatically assumed to be unrestricted**.

The import record MUST retain, when known:

- provider/platform
- model
- account/plan used for generation
- generation date
- terms/license URL and version/date when available
- commercial-use status
- watermark/attribution requirements
- user-supplied reference assets and their rights
- music/SFX/voice assets and their rights
- provenance notes

If rights are unknown, the Studio may process the file for the user's private workflow but MUST NOT label it as cleared for redistribution or publication.

## Quran layer

Quranic text is handled as a separate verified layer:

- exact surah and ayah identifiers
- canonical Arabic text from an approved Quran source
- recitation asset with its own provenance/rights record
- reciter identity/edition metadata where available
- timing markers for the displayed ayah
- no generic TTS for Quran by default

The Quran layer MUST NOT be silently rewritten, paraphrased, or altered by the video model.

## Composition

The Studio can provide operations analogous to modern editing applications:

- place Quran text on a selected region
- choose readable Arabic typography
- animate entrance/exit without altering the text
- synchronize text with the recitation
- optionally add a verified translation as a separate language layer
- mix narration/music/SFX only when their rights and levels are known
- preserve the original imported video as an immutable source asset

## Media integrity gate

Before export, validation MUST confirm:

- video stream exists
- expected resolution/frame rate is recorded
- audio stream exists when audio is requested
- audio sample rate/channels are valid
- no silent/zero-length audio track is accidentally exported
- Quran text matches its selected ayah identifier
- every externally sourced asset has a provenance record

A build requesting Quran recitation MUST fail if the final container has no valid audio stream.

## Search boundary

This feature MUST NOT make videos or generated videos appear as a result category in the Encyclopedia's normal search.

Normal search remains focused on knowledge and illustrated evidence catalogs. Imported/generated video is available only in the separate Studio workflow.

## Example

User imports an AI-generated ant video and selects:

- Surah: An-Naml
- Ayah: 27:18
- verified Arabic text
- verified recitation

Studio output:

`AI video background + Quran recitation + synchronized Arabic ayah + optional translation + provenance manifest`

The export manifest records which parts were generated by AI and which parts came from verified religious/media sources.

## Acceptance criteria

- [ ] Import accepts a user-provided video without indexing it as a search result.
- [ ] Rights/provenance record is created before publication/export clearance.
- [ ] Quran text is selected by ayah ID and rendered from an approved source.
- [ ] Recitation is a distinct media asset with provenance.
- [ ] Final export contains a valid audio stream when recitation is enabled.
- [ ] The original video remains recoverable as the source asset.
- [ ] Unknown rights never become an automatic `cleared_for_redistribution=true` state.
- [ ] AI-generated background is never presented as scientific evidence merely because it visually depicts a claim.

## Current provider checks (researched 2026-08-31)

- **Runway:** its current usage-rights help states that, as between the user and Runway, the user retains ownership and rights to uploaded and generated content and may use Runway generations commercially. Attribution is not formally required by that policy. This does not clear third-party inputs used by the user.
- **Luma Dream Machine:** current licensing documentation distinguishes subscription tiers: Free/Lite generations are personal-use only; qualifying paid plans provide commercial-use rights. Luma also warns that outputs may contain third-party rights or may not be unique.
- **Canva AI:** current AI Product Terms say users own Output to the maximum extent permitted by law, subject to specific treatment of Licensed Content and AI-generated audio; outputs may not be unique and use remains subject to Canva's terms.

These provider statements are stored as policy notes, not as permanent legal guarantees; the Studio must preserve the applicable terms URL/version/date with each imported asset.
