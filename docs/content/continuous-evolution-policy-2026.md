# موسوعة دين الله — Continuous Evolution Policy 2026

## هدف المنظومة

لا تُعامل الموسوعة كمشروع جامد يُملأ مرة واحدة ثم يُغلق. يجب أن تستمر في:

- اكتشاف المصادر والمصنفات والنسخ الجديدة أو المتغيرة دوريًا.
- مراقبة صلاحية وروابط المصادر المسجلة.
- رصد فجوات التغطية العلمية.
- إعادة التحقق من المصادر القديمة وتسجيل تغيراتها.
- اقتراح إدخالات وتحديثات جديدة بصورة آلية.
- إبقاء البرمجيات والتبعيات وGitHub Actions محدثة بصورة دورية عبر PRs آلية.
- إعادة الاختبارات والتحقق الأمني بعد كل تغيير.

## مستويات الاستقلالية

### تلقائي بالكامل

- فحص صحة المصادر دوريًا.
- اكتشاف الروابط المتوقفة أو المتغيرة.
- رصد فجوات التغطية في المجالات المسجلة.
- فحوصات provenance والحقوق والـquarantine القائمة.
- تحديثات التبعيات وActions عبر Dependabot PRs.
- الاختبارات والأمن وAntivirus وCodeQL قبل أي ترقية.

### تلقائي مع PR ومراجعة

- إضافة مصدر جديد إلى السجل.
- تحديث metadata أو edition أو رابط مصدر.
- ترقية محتوى من `candidate` إلى حالة أقوى.
- إدخال نص علمي مرخص أو public-domain.
- تحديث الترجمات والتسجيلات الصوتية.

### لا يتم تلقائيًا دون تحقق علمي/حقوقي

- نشر نص ديني جديد على أنه موثوق لمجرد العثور عليه.
- تحويل خبر تاريخي إلى حقيقة قطعية.
- نسخ كتاب محمي بحقوق النشر.
- ترقية OCR الخام إلى نص مرجعي دون تحقق بشري.
- تعديل Corpus الموثق بصورة تتجاوز مراجعة المصدر والحقوق.
- تجاوز حماية `main` أو المراجع المستقل.

## دورة التحديث

`اكتشاف → تحقق المصدر → فحص الحقوق → مقارنة/تغير → quarantine عند الحاجة → مراجعة → CI/Security → promotion إلى main → سجل تاريخي`

## عدم الإغلاق

وجود نقص في المحتوى لا يعتبر سببًا لإغلاق المنظومة أو اعتبار المشروع منتهيًا. النقص يتحول إلى فجوة متابعة قابلة للرصد، ويعاد فحصها دوريًا حتى تتوفر مادة موثقة أو رابط رسمي موثوق.

## قاعدة أساسية

التحديث التلقائي لا يعني النشر الأعمى. **الأتمتة مسؤولة عن الاكتشاف، المقارنة، الفحص، الاقتراح، وإعادة التحقق؛ أما الترقية العلمية النهائية فتظل محكومة بالمصدر والحقوق والأدلة وحماية `main`.**
