# Din Allah Media Engine — GPU Evaluation Runbook 2026

This document defines the first real-video evaluation path without placing model weights or generated videos in GitHub.

## Recommended first candidate

Start with `wan2.2` using the official `Wan2.2-TI2V-5B` checkpoint. The official project documents T2V/I2V at 720p and 24fps and states that the 5B TI2V path can run on a GPU with at least 24 GB VRAM, such as an RTX 4090. Hardware availability is checked at runtime; this document does not claim that a free hosted GPU will be sufficient.

## Free GPU route

Kaggle currently documents free GPU notebooks and a T4 x2 option, but availability is limited. Google Colab also offers free GPU access with dynamic availability and limits. These services are external execution environments, not repository dependencies.

## Run contract

1. Choose one fixed prompt from the Media Engine prompt suite.
2. Record the exact model family, checkpoint, model revision, runtime version, GPU type, generation timestamp, prompt hash, and provider/model terms.
3. Generate the video outside GitHub Actions.
4. Keep the generated video outside the repository.
5. Run `ffprobe` and the Media Engine benchmark runner against the local video.
6. Export only the compact JSON scorecard.
7. Run VBench-2.0 on the video on GPU.
8. Merge the measured VBench result into the scorecard without changing provenance fields.
9. Human-review the result before any production adoption decision.

## VBench-2.0

VBench-2.0 evaluates 18 fine-grained dimensions across five broad categories. Its official tooling supports customized-video evaluation for selected dimensions and uses GPU execution. Do not treat a VBench score as religious evidence or scientific proof.

For the first trial, prioritize dimensions that are meaningful for general generated scenes and the selected prompt. Do not claim a full 18-dimension score unless the required inputs and evaluation conditions are satisfied.

## Quran and audio boundary

The generated video is illustration only. Quran Arabic text must come from the verified Quran layer. Quran recitation must come from a verified recitation asset. Neither is generated by the video model.

## 48K boundary

The target remains high-end mastering. Native 48K generation is not required and must never be claimed unless independently demonstrated by a specific model/checkpoint with exact evidence. Upscaling or mastering to a higher output resolution is recorded as a derived transformation, distinct from native generation.
