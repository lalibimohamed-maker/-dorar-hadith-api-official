# Rechercher — Global Learning & Knowledge Intelligence Strategy 2026

## Purpose

This document freezes the expanded direction for Rechercher as a **source-grounded Islamic knowledge and learning intelligence layer**, not merely a PDF downloader or a conventional search interface.

The implementation remains human-directed, source-grounded, rights-aware, reproducible, and compatible with the project's free/open-source preference.

## Core transformation

Rechercher evolves through this chain:

`Acquire → Preserve → Validate → Extract → Structure → Connect → Explain → Practice → Retrieve → Apply → Assess → Review → Master`

A successful acquisition remains useful even if later indexing or educational enrichment fails. Learning features must never weaken acquisition persistence, provenance, rights controls, or corpus integrity.

## Frozen product pillars

1. **Global Search** — multilingual semantic and lexical search across the permitted corpus.
2. **يا بوابة العلم** — knowledge navigator that turns a question into a source-grounded investigation path.
3. **🧠 اختبر نفسك** — assessment engine with domain-appropriate tasks, not only multiple choice.
4. **🎓 علّمني** — adaptive learning paths based on prerequisite knowledge, demonstrated mastery, and learner goals.
5. **📖 اقرأ وتعلّم** — turns a book/source into an interactive learning environment while preserving access to the original source.
6. **🎙️ تلاوتي** — recording, alignment, and feedback pipeline for Qur'an recitation where a validated evaluator exists.
7. **🕌 Tajweed learning** — rule-aware practice and feedback; never claim automatic correction without a real evaluator.
8. **📚 Knowledge Graph** — relationships among works, authors, narrators, concepts, events, schools, evidence, and sources.
9. **🗂️ Flashcards + spaced review** — retrieval-centered review generated from source-grounded knowledge.
10. **🌍 World-language learning layer** — interface language, learning/explanation language, and source language remain distinct.
11. **📈 Mastery dashboard** — progress, confidence, recall, application, weak concepts, review queue, and source coverage.
12. **🔎 Research mode** — evidence-first exploration with explicit source provenance and uncertainty.

## Evidence-driven learning methods

The learning engine should combine, where appropriate:

- retrieval practice;
- spaced practice;
- interleaving;
- elaboration;
- concrete examples;
- dual coding;
- worked examples followed by fading support;
- self-explanation;
- concept mapping;
- formative assessment;
- corrective feedback;
- reflection and metacognitive prompts;
- transfer/application tasks;
- cumulative review;
- low-stakes practice before high-stakes assessment.

Research supports spacing/retrieval as robust learning strategies, while a 2025 meta-analysis found retrieval's advantage over elaborative conditions was conditional on feedback. The engine therefore must pair retrieval with meaningful corrective feedback rather than treating a quiz score as the end of learning.

Assessment must match the knowledge type.

| Domain | Preferred assessment modes |

| Tajweed | rule identification, examples, listening, controlled recitation |
| Hadith | source identification, takhrij, narrator relations, grading concepts, comparison |

| Fiqh | practical cases, madhhab comparison, evidence mapping |
| Usul al-Fiqh | applied principles and reasoning |

| Books of the Salaf | author/work/era/topic/source relationships |

## Mastery model

A learner should not be considered proficient from a single correct answer. Track separate dimensions:

- recognition;
- recall;
- explanation;
- application;
- discrimination between similar concepts;
- transfer to a new case;
- source navigation;
- confidence calibration;
- retention over time.

A mastery state must therefore be evidence-based and reversible when later retrieval shows weakness.

## Adaptive learning

The adaptive engine should use a learner model containing:

- goals;
- language preferences;
- known prerequisites;
- demonstrated mastery;
- error history;
- review intervals;
- confidence;
- preferred modality;
- current cognitive load signals where available;
- source/rights availability;
- accessibility requirements.

The system may recommend the next activity, but it must remain explainable: **why this activity, why now, and which source supports it?**

## Knowledge graph

The graph should support entities and relations such as:

`Author → Work → Edition → Chapter → Passage → Concept → Evidence → Narrator → Hadith → Event → Place → School → Scholar → Commentary → Translation`

Each relationship must retain provenance and confidence. A graph relation is an indexed claim, not automatically a declaration of truth.

Knowledge graphs are particularly relevant because educational research identifies applications in personalized learning, curriculum design, concept mapping, recommendation, semantic search, and question answering.

## Ya Bawabat al-Ilm

The navigator should convert a question into a research path:

`Question → intent/domain → candidate concepts → primary/secondary sources → evidence → scholarly positions → uncertainty → explanation → practice → further reading`

For disputed issues it must expose the disagreement rather than silently collapse it.

It must distinguish:

- source existence;
- text extraction;
- attribution;
- authenticity/gradation;
- scholarly interpretation;
- project indexing;
- AI-generated explanation.

## Read & Learn

Every rights-permitted source can progressively expose:

- original document/PDF;
- searchable text;
- OCR where applicable;
- chapter navigation;
- vocabulary and terminology;
- source-linked explanations;
- concept map;
- flashcards;
- questions;
- practice tasks;
- review queue;
- citations back to the exact source location.

Rights-unknown material remains governed by the existing rights policy and must not become publicly downloadable merely because a learning layer exists.

## Qur'an and recitation architecture

`Canonical Qur'an → reference recitations → curriculum/rules → recorder → alignment → evaluator → error report → feedback → repeat → spaced review`

The architecture may support speech recognition, word alignment, pronunciation analysis, Tajweed-rule detection, memorization tracking, missing-word completion, and adaptive feedback. However, AI remains complementary to qualified teaching and traditional transmission; the product must not claim authoritative recitation correction unless a validated evaluator actually produced the result.

## Multilingual world layer

Language is modeled as three independent dimensions:

1. **Interface language** — navigation and controls.
2. **Learning language** — explanations, questions, feedback, and study plan.
3. **Source language** — original Arabic or another source language.

This permits, for example, a French learning session using Arabic source text, a verified French translation, Arabic terminology, and source-linked references.

The architecture must be extensible beyond the initial launch locales. Multilingualism is a learning design requirement, not merely UI translation.

## Accessibility and Universal Design

The learning environment should provide multiple means of:

- engagement;
- representation;
- action and expression;
- language support;
- comprehension;
- feedback.

Support keyboard navigation, screen readers, adjustable text, high contrast, captions/transcripts, audio alternatives, reduced motion, and clear error recovery. CAST's UDL Guidelines 3.0 (2024) provide a current evidence-informed framework for reducing barriers and supporting learner variability.

## New strategic additions from the 2026 global review

### A. Evidence-to-feature registry

Every major learning feature should record:

`feature → pedagogical mechanism → evidence → implementation → evaluation metric → limitations`

This prevents fashionable AI features from entering the product without an educational rationale.

### B. Experimentation and A/B evaluation

Learning features should be evaluated with safe, privacy-preserving experiments where practical. Metrics should include retention, transfer, completion, error recovery, time-to-mastery, source engagement, and learner confidence—not clicks alone.

### C. Explainable recommendations

Every adaptive recommendation should be inspectable:

> Recommended because you missed X twice, prerequisite Y is weak, and review interval Z is due.

### D. Contradiction-aware research

The system should identify conflicting source claims and scholarly disagreements instead of merging them into one synthetic answer.

### E. Confidence calibration

Users should periodically answer with confidence ratings. The system can then distinguish:

- know + confident;
- know + uncertain;
- don't know + confident;
- don't know + uncertain.

The dangerous state is false confidence, not merely wrong answers.

### F. Transfer laboratory

After learning a rule, the learner receives a novel case requiring application. This tests whether the learner can transfer knowledge beyond the exact training example.

### G. Teach-back mode

The learner explains a concept in their own words. The system checks coverage against source-grounded concepts and asks targeted follow-ups. It must not grade theological truth from an unconstrained model alone; source alignment and human review remain authoritative where required.

### H. Socratic dialogue mode

Instead of immediately answering, the tutor may ask guided questions to reveal assumptions, retrieve prior knowledge, and build reasoning step by step.

### I. Research apprenticeship

A dedicated mode trains users to conduct Islamic research:

`question → search → source evaluation → chain/provenance → comparison → note-taking → citation → synthesis → uncertainty statement`

### J. Source-first generation

Generated questions, explanations, summaries, and flashcards must be traceable to source passages. Unsupported generated facts must not enter the canonical corpus.

### K. Cognitive-load controls

Do not overwhelm the learner with long answers by default. Offer progressive disclosure:

`short answer → evidence → explanation → deep dive → original source`

### L. Cross-modal learning

Where source rights permit, support text, audio, diagrams, timelines, concept maps, tables, and interactive exercises. Modalities should complement rather than duplicate each other unnecessarily.

### M. Interleaved curriculum

Review related but distinguishable concepts in mixed sessions rather than blocking all practice into one category. This is especially useful for confusing terminology, hadith sciences, fiqh distinctions, and Arabic forms.

### N. Prerequisite graph

Learning paths should know that some concepts depend on others. A learner struggling with an advanced topic should be routed to the weakest prerequisite rather than repeatedly shown the same advanced explanation.

### O. Personal research library

Allow learners to bookmark source passages, create private notes, attach questions, and build personal collections while preserving the canonical source and provenance separately.

### P. Teacher/scholar review channel

Where a feature affects religious interpretation or authoritative educational judgment, provide a route for qualified human review. AI can prepare evidence and organize material; it does not become the religious authority.

### Q. Offline/PWA resilience

Core reading, cached learning plans, downloaded rights-permitted materials, flashcards, and review queues should work with intermittent connectivity where technically feasible. Synchronization must preserve provenance and avoid silently overwriting progress.

### R. Open/free-first implementation

Prefer standards, open-source libraries, local/browser processing, public datasets with compatible licenses, and reproducible pipelines. Avoid architectural dependence on a paid proprietary API.

### S. Privacy by design

Learning history, voice recordings, and personalization data should be minimized, locally processed where feasible, clearly scoped, exportable/deletable, and never silently repurposed for unrelated uses.

### T. Safety and epistemic integrity

The system must clearly distinguish:

`canonical text | source text | translation | scholarly interpretation | indexed metadata | learner-generated note | AI-generated explanation`

No layer may silently overwrite another.

## Architecture boundary

These additions are a learning/intelligence layer above Rechercher acquisition. They must not weaken:

- PDF acquisition persistence;
- secondary LFS serialization;
- source reachability quarantine;
- rights controls;
- provenance;
- immutable source hashes;
- OCR validation;
- security workflows;
- protected main branch;
- required checks.

## Definition of done for the strategic layer

The project should eventually be able to demonstrate:

1. A source can be acquired and preserved independently of later enrichment.
2. A source can be searched in multiple languages without replacing the original source language.
3. A source can generate traceable learning objects when rights permit.
4. Learning objects can use retrieval, spacing, interleaving, elaboration, examples, and feedback.
5. Users can move from question → evidence → explanation → practice → review.
6. Adaptive recommendations are explainable.
7. Knowledge graph relations retain provenance.
8. Qur'an learning preserves canonical Arabic text and does not falsely claim AI authority.
9. Religious interpretation remains source-grounded and human-reviewable.
10. Accessibility and multilingual learning are first-class requirements.
11. Learning analytics measure durable learning rather than engagement alone.
12. All additions remain compatible with the project's free/open-source and rights-aware principles.
